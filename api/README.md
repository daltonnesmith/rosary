# Managed profile function

Deploy `api/` as the **managed** Static Web Apps API, on Node 22. Its anonymous Functions HTTP trigger trusts identity headers **only behind SWA**; never expose it as a directly reachable Function App. Restrict `/api/profile` to the `authenticated` role in SWA routing as well. Do not enable cross-origin access. Set `STILLWATER_STORAGE_CONNECTION` in server application settings only. Provision the private `profiles` container separately; the function needs blob read/write/delete access and never creates containers. Keep request bodies, principal headers, and storage credentials out of diagnostics.

From the repository checkout run `npm --prefix api ci`, `npm --prefix api run build`, and `npm --prefix api test`. Build before packaging: `copy-validator.mjs` copies `src/core.js` and its transitive modules to `api/shared/` with their relative imports intact. Include that generated directory and the production SDK dependency in the API deployment, **not** in the static site. If the deployment builder receives only `api/`, run the build in the parent checkout first and use the prebuilt API. Tests use the actual validator and an in-memory conditional blob double; no Azure account is required.

Send `X-Stillwater-Account` with the signed-in SWA principal's exact `userId` on **every** call. GET returns `{state,version}` (both null when absent). PUT JSON `{state,version}` creates with `null`, otherwise updates with the previously returned quoted ETag. DELETE JSON `{version}` requires that ETag. Successful writes return the resulting `{state,version}`. On `409` refetch before deciding how to reconcile; do not retry an unconditional write. `401` means no authenticated identity, `403` an account mismatch. Write requests require `application/json` and are limited to 2,000,000 bytes including the envelope.
